# Invest in improvement loops

A direct improvement raises the current level. Investing in a mechanism that
turns use into lasting improvement can keep raising it. A modest starting point
can overtake a much better fixed one if use keeps making it better.

**Even better.** The mechanism does not have to improve itself. If it does,
later cycles also become more effective, and the loop compounds.

**Example.** A skill can extract evidence from each use and turn it into a small
lasting improvement. The extraction process can stay unchanged while the skill
gets better over time. If better skill behavior also supports better later
refinements, the loop compounds. This is one implementation, not the definition
of the principle.

**Increase the value of the cycle.** Ask, "How can you increase the value of the
cycle?" Possible levers include:

- Lower the friction of starting a run, and standardize how runs work, so you
  can run the cycle more often.
- Make simulated runs resemble the user's real story so their lessons transfer
  to actual use.
- Increase the incremental improvement from each run. Make results easier to
  view and grade, triage what matters, and identify issues worth fixing.

These are ways to strengthen the loop, not the definition of it.

**The rule.** Repetition alone is not an improvement loop. Use must feed back
into lasting improvement over time. When repeated use can repay the investment,
prefer improving that mechanism over squeezing a little more quality out of the
current instance. The loop can keep producing gains. A direct improvement
produces one fixed gain.

**The takeaway.** Anders heavily prioritizes spending effort on designing the
mechanism that lets a system become stronger through use. This often creates
much more value than another direct improvement. Even better if the mechanism
also strengthens and compounds.
