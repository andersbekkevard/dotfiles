# Compound the improvement loop

The best one-off improvement eventually loses to a system that becomes stronger
through use. A modest starting point can overtake a much better fixed one if
each cycle improves what the next cycle can do.

**Even better:** An incremental system gets better over time. A compounding
system also improves its ability to improve.

**Example.** Working out builds fitness. Greater fitness makes the next workout
less uncomfortable, which leads to working out more, which builds more
fitness. The result of one cycle strengthens the mechanism that produces the
next.

**One implementation.** A skill can extract evidence from each use and turn it
into a small lasting improvement. Better skill behavior can then make later
uses more productive and support better refinements. This is one way to build
the loop, not the definition of it.

**Increase the value of the cycle.** Ask, "How can you increase the value of the
cycle?" Possible levers include:

- Lower the friction of starting a run, and standardize how runs work, so you
  can run the cycle more often.
- Make simulated runs resemble the user's real story so their lessons transfer
  to actual use.
- Increase the incremental improvement from each run. Make results easier to
  view and grade, triage what matters, and identify issues worth fixing.

These are ways to strengthen the loop, not the definition of it.

**The rule.** Repetition alone does not compound. Each gain must make later gains
easier, faster, more likely, or more valuable. Prefer spending effort on this
mechanism over squeezing a little more quality out of the current instance. The
mechanism keeps paying back. The one-time improvement does not.

**The takeaway.** Anders heavily prioritizes spending effort on designing the
system so that it becomes stronger through use. Even better if that mechanism
also strengthens and compounds.
